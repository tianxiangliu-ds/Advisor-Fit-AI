# 导师双选 AI 工具（MVP）

证据驱动的导师理解与匹配助手。输入一份 CV 与一位导师官方主页 URL，经人工确认学生事实与作者身份后，产出带来源的导师画像、可解释匹配分析与事实受控的中文邮件草稿。

> 完整立项与技术可行性分析见 `outputs/导师双选AI工具-MVP立项与技术可行性分析.md`，实施计划见 `outputs/导师双选AI工具-v0.1-MVP实施计划.md`。

## 一句话定义

> 一个面向中国高校硕博双选的、以公开证据为基础的单导师研究与匹配助手：把导师官方页面与近年论文整理成可核验画像，指出学生的真实匹配点与缺口，并生成事实受控、需人工确认的中文联系邮件草稿。

## 产品边界（v0.1）

**做**：单导师研究（一份 CV + 一个官方 URL）、身份消歧（重名必须人工确认）、带证据画像、分维度匹配、受控邮件草稿、Markdown/JSON 导出、一键删除。

**不做**：姓名自动搜索、批量导师、全国导师库、自动群发/自动找邮箱/自动跟进、Google Scholar/CNKI/百度学术爬虫、LangChain/LangGraph/MCP/多 Agent/向量数据库、黑箱百分比、推断导师人品/团队真实规模/招生名额。

## 技术栈

Python 3.12+ · Streamlit · Pydantic v2 · SQLite（标准库 `sqlite3`）· httpx · BeautifulSoup + trafilatura · pypdf · OpenAlex API · OpenAI 兼容 LLM 接口（可替换，经 provider 隔离）· pytest / respx / ruff。

## 安装与启动

```bash
# 1. 安装依赖（需 uv）
uv sync

# 2. 配置（可选）：LLM 与学术 API 均可不配置，流程会降级为确定性规则
cp .env.example .env
#   编辑 .env，填入 LLM_API_KEY / LLM_MODEL（不填则邮件草稿为空、匹配仍可用）

# 3. 启动
uv run streamlit run app.py
```

五步向导：① 上传 CV + 输入官方 URL → ② 确认学生事实 → ③ 确认导师身份（作者消歧）→ ④ 证据化画像与匹配报告 → ⑤ 邮件草稿、导出与删除。

## 测试与评测

```bash
uv run pytest -q                 # 全量测试
uv run ruff check src tests scripts app.py
uv run python scripts/run_evals.py   # 金标准评测，任一闸门失败则退出码 1
```

## 数据源

- **核心**：用户给定的学校官方主页（记录最终 URL、抓取时间、robots 状态、内容 hash）。
- **学术**：OpenAlex（作者候选 + 近 5 年论文，含磁盘缓存与 429 退避）。
- **不接入**：Google Scholar、CNKI、百度学术；v0.1 不做姓名搜索。

## 隐私模型

- CV 仅本地解析；发送给 LLM 前删除姓名、邮箱、电话、地址等直接标识符。
- 原始 CV 不入库、不入导出、不入 Git；测试仅用匿名 fixtures。
- API Key 只存 `.env`，不进前端与日志。
- 运行数据本地 SQLite（`data/`），支持一键删除。

## `UNKNOWN` 的含义

系统严格区分 `FACT / INFERRED / UNKNOWN`。`UNKNOWN` 表示“未提供/未找到证据”，**不得**被改写为肯定或否定事实。例如：未找到招生声明时输出“未发现公开招生信息”，绝不写成“不招生”；团队只报“公开页面列出 N 位成员”，绝不推断真实规模。

## 已知限制

- 身份消歧：姓名只用于召回，确认需强证据（ORCID/DBLP/OpenAlex/官方 DOI 重合）；证据不足时停止，不自动冒进。
- 官网异构/过时/无法访问：提供“粘贴页面文本”降级。
- 论文信息过少：只输出官网声明与“证据不足”，不做趋势判断。
- 招生/团队状态：仅接受带日期的明确声明，否则 `UNKNOWN`。
- 主题趋势：需 ≥3 篇已确认论文、跨 ≥2 个年份才输出，单篇热点不算“转向”。

## 禁止批量套磁

本工具不提供发送能力，也不支持批量、自动跟进或群发。请尊重收件人与邮箱服务商的反骚扰要求，逐封人工确认后自行发送。
