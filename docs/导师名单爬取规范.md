# 高校导师名单爬取规范（以武汉大学为样板）

> 这份文档记录**怎么把一所高校的导师名单完整、正确地抓下来**。
> 它来自武汉大学的实际踩坑与修正，任何 Agent 照着做都能复现同样的结果。

---

## 一、目标与三条底线

**目标**：拿到该校「学院 → 导师姓名 → 职称/邮箱/研究方向」的完整名单。

**三条底线**（按优先级）：

1. **不能有错**：界面词（`师资队伍`、`常用下载`、`宣传片`、`全职教师`）绝不能当成人名。
2. **不能漏**：**没有任何一个学院应该得到 0 人**。如果某个学院是 0，说明流程有问题，必须排查。
3. **宁缺勿错**：拿不准的字段（职称、研究方向）宁可留空，也不填一个错的进去。

---

## 二、总体思路：三层结构

```
① 发现层：学校首页 → 院系目录 → 各学院官网
② 提取层：学院官网 → 师资页 →（必要时）多层分类页下钻 → 姓名 + 字段
③ 复核层：规则过滤 → 大模型逐条判定 → 规范化 → 写库
```

---

## 三、每一层的具体做法与坑

### ① 发现层：找学院目录

**做法**
1. 抓学校首页，收集所有链接。
2. 挑出文本含「院系设置 / 学院设置 / 组织机构 / 教学单位 / 院系」的链接 —— **不要只取第一个**，
   依次尝试所有候选，选"能解析出最多学院"的那个。
3. 还找不到，就从「学校概况 / 组织机构」这类页面再找一层。
4. 若首页本身列了学院，直接用。
5. 排除"学院名"是笼统词（`学院（系）`、`教学单位`）的条目，它们本身是列表页，要**再展开一层**。

**踩过的坑**
- ❌ 只取首页第一个候选入口 → 8 所学校一个学院都没找到。
- ❌ 把 `学院（系）` 当成一个学院 → 漏掉它下面的真实学院。
- ❌ 静态抓到的首页是空壳（JS 渲染）→ 需要浏览器渲染（Playwright）兜底。

### ② 提取层：从师资页拿姓名

**做法**
1. 在学院官网里找「师资队伍 / 师资力量 / 教师名录 / 专任教师 / 导师队伍」等入口；
   找不到就按 URL 特征猜（`szdw`、`shizi`、`teacher`、`faculty`、`jsml`）。
2. 从师资页提取姓名，**两条路并用**：
   - **短链接**：锚文本本身就是 2–4 个汉字的名字 → 直接是姓名。
   - **卡片链接**：整张人物卡片包在一个 `<a>` 里，锚文本是「姓名+单位+职称+邮箱」连成的长串
     （例：`龚韵武汉大学空间科学与技术系副主任，教授yun.gong@whu.edu.cn`）→
     需要剥掉邮箱与职称，再按"后面是否紧跟地名/校名"切出姓名。
3. 并行解析表格：`<tr>` 里若是「姓名 | 职称 | 研究方向 | 邮箱」分列，按列取值。

**关键：递归下钻**（这是最容易漏人的地方）
- 很多学院的师资页只是一个**分类目录**：`专任教师 / 实验人员 / 管理人员`、
  `国内师资 / 国外师资`、`按系所`……
- 必须顺着这些分类入口**递归往下走，最多 3 层**，取人最多的那一支。
- **候选链接不要截断**！杜伦联合学院的「国内师资 / 国外师资」排在第 30 个链接之后，
  曾经因为"只扫前 30 个"而整院漏掉。

**踩过的坑**
- ❌ 只扫前 N 个链接 → 漏掉排在后面的分类入口。
- ❌ 只认「系/所/中心」这类分类词 → 漏掉「专任教师/国内师资/外国师资」。
- ❌ 只处理"锚文本就是姓名"的链接 → 卡片式页面整院为 0。
- ❌ 分页未处理 → 名单只有第一页（当前版本的已知缺口，见第六节）。

### ③ 复核层：把界面词挡在门外

**第一道：规则过滤**（离线可跑）

判据：**2–4 个汉字 且 不含任何界面词根**。

- 界面词根示例：`服务 下载 师资 宣传 培训 教师 教授 导师 学院 大学 中心 简介 概况
  通知 公告 招生 招聘 党建 工会 学生 研究生 培养 队伍 名录 项目 成果 制度 指南 …`
- ⚠️ **不要把「新闻」「文化」「方向」「科学」「信息」「国际」当词根** ——
  「郭新闻」「李文化」「方向忠」都是真实存在的教授姓名。
- ⚠️ **不要把"首字是常见姓氏"作为硬条件** —— 「闫永达」「玄玉波」「初剑峰」姓氏不在常见表里，
  强制要求会造成漏采。姓氏只能当可信度参考。
- 兜底：同一个词出现在同一所学校的 **6 个以上学院**，必是站点导航，丢弃。

**第二道：大模型复核**（需要 LLM_API_KEY）

把候选名单连同页面正文交给大模型，逐条判断"是导师姓名 / 是界面词"。
提示词要点：
- 明确告知 `师生服务`、`常用下载`、`国内师资`、`宣传片`、`高端培训`、`全职教师` 是界面词；
- 明确告知 `郭新闻`、`李文化`、`方向忠`、罕见姓氏、外籍姓名**都算人名**；
- 要求只返回与原文完全一致的条目，不确定的不要返回。

**第三道：规范化（保人，不删人）**

```
董陇军副教授   → 董陇军      （剥职称后缀）
工研院胡耀武    → 胡耀武      （剥单位前缀）
薛 渊          → 薛渊        （去空格）
Kok-MengLee   → 保留        （外籍姓名不规范化）
全部导师 / CYC / 某院放疗科  → 删除（真正的栏目名/垃圾）
```

**这一条是被真实误删逼出来的**：早期版本按"命中词根就删"，会删掉 `郭新闻` 这类真人。
现在的规则是**先规范化保住人，只删"绝不可能出现在姓名里"的栏目词**。

## 四、数据规范（写库要求）

一位导师一行，按 **(学校, 学院, 姓名)** 定位 —— **同一人在多个学院挂名时各留一行**（不重不漏）。

| 分组 | 字段 | 说明 |
|---|---|---|
| 身份 | `university` / `department` / `name` / `note` | `note` 存姓名里的括号备注，如「深圳,千人计划」 |
| 了解他 | `title` / `email` / `research_directions` / `research_areas` / `publications` / `homepage_url` / `profile_text` | 拿不到就留空，**不许猜** |
| 唯一标识 | `orcid` / `openalex_id` | 靠学术库匹配，不靠官网 |
| 可追溯 | `sources` / `source_url` / `retrieved_at` / `content_hash` / `field_sources` | `field_sources` 记录**每个字段分别来自哪个来源** |
| 评价 | 另一张 `reviews` 表 | 一位导师可有多条；只作参考，不进导师资料字段 |

**合并规则**：新来源**只补空字段、不覆盖已有值**，并记下该字段的来源。

---

## 五、验收标准

一所学校爬完后，逐条检查：

1. **每个学院都不为 0**（这是硬指标）。有 0 就必须排查是哪种情况：
   - 「未找到师资入口」→ 换个关键词或按 URL 猜；
   - 「页面无姓名链接」→ 先试浏览器渲染，再试递归下钻；
   - 「下钻后仍为 0」→ 大概率是分页或纯图片名单，记入已知缺口。
2. 抽查 3 个学院，人名逐一核对**是不是真人**（含职称/邮箱的更好）。
3. 全库跑一遍界面词过滤，**残留应为 0**。
4. 已知真人姓名不得被误删（回归清单：`郭新闻`、`李文化`、`方向忠`、`闫永达`）。

## 六、当前已知缺口（诚实记录）

| 缺口 | 影响 | 计划 |
|---|---|---|
| **分页未处理** | 名单只取第一页，人数可能偏少 | 后续版本解析「下一页」 |
| **图片式名单** | 部分学院用图片列名单，抓不到文字 | 需要 OCR |
| **纯 JS + 反爬（412）** | 少数站点（如北邮）直接拒绝程序访问 | 需要更强的浏览器指纹模拟 |
| **字段完整度低** | 职称/邮箱/研究方向需逐个进详情页，代价高 | 用大模型批量抽取详情页 |
| **医院类学院结构特殊** | 第一/第二临床学院（医院官网）结构完全不同 | 单独适配 |

## 七、可直接复用的提示词

> 把下面这段交给任何 Agent（配好 `LLM_API_KEY`），它就能按同样标准爬一所学校。

```
你是高校导师名单采集 Agent。任务：抓取【{学校名}】的【{官网首页}】，
产出该校「学院 → 导师姓名 → 职称/邮箱/研究方向」的完整名单，写入
data/advisors.db 的 advisors 表（按 学校+学院+姓名 定位）。

必须遵守的三条底线：
1. 不能有错：网页界面词（师资队伍/常用下载/宣传片/全职教师/师生服务/国内师资/
   学院简介/现任领导）绝对不能当成人名。
2. 不能漏：**没有任何一个学院应该是 0 人**。任何学院为 0，都必须排查原因并重试，
   不允许直接把 0 当作结果交差。
3. 宁缺勿错：职称/邮箱/研究方向拿不准就留空，不许猜。

采集流程（四步，每步都要记录日志与结果）：

【第 1 步 · 找学院目录】
- 抓首页，收集所有像「院系设置/学院设置/组织机构/教学单位/院系」的链接，
  不要只取第一个：逐个尝试，选能解析出最多学院的那个。
- 若首页本身列了学院，直接用。
- 若出现「学院（系）」「教学单位」这类笼统条目，它本身是列表页，要再展开一层。
- 静态抓取拿到的是空壳（正文<200字 或 链接<5个）时，改用浏览器渲染（Playwright）重抓。

【第 2 步 · 找师资页并提取姓名】
- 在学院官网找「师资队伍/师资力量/教师名录/专任教师/导师队伍」，找不到按
  URL 特征猜：szdw / shizi / teacher / faculty / jsml。
- 姓名有两条来源，都要用：
  (a) 锚文本本身是 2–4 个汉字的短链接 → 直接是姓名；
  (b) 卡片式链接（锚文本是「姓名+单位+职称+邮箱」的长串，如
      "龚韵武汉大学空间科学与技术系副主任，教授yun.gong@whu.edu.cn"）
      → 剥掉邮箱与职称，再按"后面是否紧跟地名/校名（武汉/北京/清华/大学/学院…）"
        切出姓名，不要把"武汉"当成名字的一部分。
  (c) 表格：<tr> 里若是「姓名|职称|研究方向|邮箱」分列，按列取值。

【第 3 步 · 递归下钻（最容易漏人的地方）】
- 若某个学院提取到的姓名 < 3 个，说明这一页只是分类目录（如
  「专任教师/实验人员/管理人员」「国内师资/国外师资」「按系所」）。
- 顺着这些分类链接递归往下走，**最多 3 层**，取人最多的那一支。
- **候选链接不要截断**：不要只扫前 20/30 个链接，很多分类入口排在页面很后面。
- 若仍 < 3 个，强制用浏览器渲染该页再提取一次。

【第 4 步 · 复核与规范化】
- 规则：姓名必须是 2–4 个汉字，且不含界面词根（服务/下载/师资/教师/教授/学院/大学/
  中心/简介/概况/通知/招生/党建/工会/学生/培养/队伍/项目/成果/制度/指南…）。
  注意：「新闻」「文化」「方向」「科学」「信息」「国际」**不能**当词根，
  因为「郭新闻」「李文化」「方向忠」是真实教授姓名。
  注意：不要强制要求"首字是常见姓氏"，否则会漏掉「闫永达」「玄玉波」这类罕见姓氏。
- 大模型复核：把候选名单连同页面正文交给 LLM，逐条判定"人名 / 界面词"。
  必须明确告诉它：郭新闻、李文化、方向忠、罕见姓氏、外籍姓名都算人名；
  师生服务、常用下载、国内师资、宣传片、全职培训、全职教师不算。
- 规范化（保住人，不要删人）：
  剥职称后缀（副教授/教授/讲师/研究员…）、剥单位前缀（工研院/XX学院…）、去空格；
  外籍姓名保持原样。「全部导师」「CYC」「某院放疗科」这类才删除。
- 同一词出现在 6 个以上学院 → 判定为站点导航，丢弃。

【写库要求】
- 一位导师一行，主键 (学校, 学院, 姓名)；同一人在多学院挂名时**各留一行**。
- 字段：university, department, name, note, title, email, research_directions,
  research_areas, publications, homepage_url, profile_text, sources, source_url,
  retrieved_at, content_hash, field_sources。
- 合并时**只补空字段、不覆盖已有值**，并在 field_sources 里记下该字段来自哪个来源。

【交付前自检（必须逐条报告）】
1. 每个学院各采到多少人？**有没有 0 人的学院？** 有就说明原因并重试。
2. 全量跑一遍界面词过滤，还剩多少条？（应为 0）
3. 抽查 3 个学院，列出人名供人工核对。
4. 报出各字段的填充率（职称/邮箱/研究方向的覆盖率）。
```
