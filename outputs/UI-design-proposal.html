导师双选 AI 助手 · UI 设计方案

面向中国高校硕博套磁场景 · 美观、可信、可验证

一、设计目标

本方案在保留现有 v0.1 离线、人工核验、证据可溯三大安全底座的前提下，对界面进行重新设计，核心目标是：

  • 降低认知负荷：将原本纵向堆叠的 4 个步骤改为「步骤导航 + 卡片化工作区」，让用户始终清楚当前在哪一步、下一步做什么。
  • 强化证据语义：通过颜色、图标、标签把「已确认 / 待审核 / 疑似同名 / 证据不足」四种状态可视化，避免用户误用未核实信息。
  • 提升信任感：用清晰的来源引用、可展开的原文链接、版本化历史记录，让用户对 AI 产出「看得懂、敢使用」。
  • 适配 Streamlit：所有设计均可在 Streamlit 中通过原生组件 + 自定义 CSS 实现，无需引入新的前端框架。

二、设计原则

1. 渐进式披露

把复杂流程拆为 4 个步骤，每个步骤只暴露当前必需字段。高级选项（如英文检索、机构覆盖）默认折叠，需要时展开。

2. 状态即反馈

每个事实、每篇论文、每个匹配维度都用明确的徽章（badge）表达状态，减少用户的记忆负担。

3. 来源可追踪

报告中的每句话、每个结论都支持「查看证据」——学生事实来自 CV 哪一行，导师事实来自哪篇论文。

4. 中文优先、克制表达

避免夸张、讨好的文案；按钮文案使用动词短语，如「解析简历」「确认事实」「生成报告」。

七、交互与动效建议

  • 步骤切换：用户完成当前步骤并点击「下一步」后，步骤导航以 200ms 过渡高亮下一步；未完成必填项时，错误字段以红色边框和提示文案聚焦。
  • 论文核验：Agent 检索结果返回时，候选论文按「匹配 / 需审核 / 疑似同名」分组以 150ms 交错动画出现，避免一次性信息冲击。
  • 报告生成：生成报告期间，工作区显示骨架屏；完成后自动滚动到报告顶部，并弹出「报告已生成」轻提示。
  • 历史记录：侧边栏历史条目 hover 时显示「查看 / 对比 / 删除」操作，删除前需二次确认。

八、Streamlit 实现建议

本设计完全可在现有 Streamlit 架构内实现，无需新增前端框架。推荐做法：
  • 用 st.columns + st.container 构建两栏/卡片布局；关键模块用 st.markdown(..., unsafe_allow_html=True) 注入自定义 CSS 类。
  • 用 st.session_state.step 控制当前步骤，按钮触发状态切换并 st.rerun()。
  • 候选论文用 st.checkbox + st.expander 分组；论文状态用 st.badge 风格的小标签实现。
  • 报告页用 st.metric 展示核心结论，用 st.progress 或自定义 CSS 条形图展示匹配维度。
  • 邮件草稿使用 st.text_area，并在下方放置 st.download_button 与复制按钮。
